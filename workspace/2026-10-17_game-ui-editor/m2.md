## Implemented in source

- A versioned visual-project document, separate from the validated M1 Unity
  document, keeps existing GE synchronization files compatible.
- Create a named portable HUD project beside the currently opened project and
  reopen saved projects from that folder. The project keeps its document,
  original assets, font files and private runtime files in separate locations.
- Import a full-screen reference and separate PNG, JPEG or WebP artwork. Mark a
  rectangle on the reference to create a non-destructive cropped image element.
  Import TTF, OTF, WOFF or WOFF2 fonts and assign them separately from text.
- Edit a hierarchy of containers, text, buttons and images. Reparent or remove
  nodes, drag and resize them, order sibling layers, and use fixed/free anchors,
  visual guides and horizontal or vertical container layouts.
- Turn an element into a shared component, duplicate instances and keep explicit
  per-instance overrides when shared defaults change. Inspect and reset individual
  overrides with undo support. Image borders support nine-slice settings over
  non-destructive crops, with derived previews and intact original artwork.
- Switch the preview between 16:9 and 21:9, with sizing fitted to the editor
  window. Save, undo, redo and restore the previous saved version. Missing
  imported assets are reported.

Project assets use content-addressed files inside the portable folder. The M1
GE pilot retains its existing format and Unity round-trip behavior. M2 projects
are visual documents and do not claim Unity integration.

## Automated verification

Run `npm.cmd run test:verify` in `E:\MrMak\GameUIEditor` from a Mak terminal or
agent session. It builds the interface and prepared runtime, runs the core tests,
and runs eight scenarios in both Edge and Windows WebView2. Temporary projects,
profiles and executable copies keep the normal application separate.

- Cold startup, editable geometry, local undo/redo, previous-save recovery,
  reload and reopening another saved project.
- Shared text, size and font-size changes with explicit instance overrides.
- Reference import and crop size, reuse of original image assets, imported font
  loading, and a copied project reopened after its upload paths become unavailable.
- PT-BR/English, 16:9/21:9 and 1440/768/390 pixel content viewports, including a
  long project title and light/dark OS preferences. The editor keeps its dark palette.
- Horizontal/vertical containers, padding/spacing, sibling layer order and
  reparenting, including save/reload.
- Stable anchor margins across aspect ratios, anchor-aware guide snapping and
  screen dimension edits that keep the canvas/root/guides consistent.
- Nine-slice rendering over a cropped source region, with original asset bytes
  preserved. Border bounds are checked against the crop and effective component.
- Visible/resettable instance overrides and incomplete color/number entry that
  retains the last valid document instead of throwing UI exceptions.

These checks reproduced and helped fix geometry field paths, component override
resolution, duplicate positioning, crop sizing, repeated asset imports, local
redo at a saved state, selection after saves, accessible text input labels and
header overflow. Follow-up checks also fixed shared-default aliasing, anchored
dragging, crop-aware stretch borders, invalid hierarchy acceptance and inconsistent
screen resizing. Earlier cold-start authorization initialization was also fixed.

See [automated testing and captures](testing.html). Full local Playwright results
are at `E:\MrMak\GameUIEditor\.local\e2e-report\index.html`.

## Delivery limits and release checks

- The owner's manual feedback was general rather than an itemized acceptance
  log. Follow-up fixes have automated browser/Windows proof; no separate new
  owner approval of their appearance is claimed.
- Automated artwork fixtures are synthetic. A real GE capture and panel were
  supplied for the owner's review; this does not imply M2 Unity integration.
- Installer/update acceptance belongs to M6. Native file-picker use and physical
  window resizing are outside the automated suite; imports use the file input
  directly, and narrow sizes emulate the WebView content viewport.
- The current runtime is prepared and verified in isolated packages. The user's
  normal running application was not restarted to install these follow-up fixes.
