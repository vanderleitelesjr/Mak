## Implemented

- Schema 4 uses the existing visual document for Unity rendering and the shared
  project owner for comparison, explicit conflict choices, application and recovery.
  M2/M3 files migrate in memory; their first save keeps an original-format backup.
- Native UI Toolkit rendering covers authored hierarchy, layouts, anchors,
  components/overrides, PNG/JPEG artwork/crops/nine-slice, TTF/OTF fonts and behavior.
- Eight identified blocks preserve the existing GE resources, selection,
  command grid, minimap, tooltips, idle workers, mode hints and match screens.
  Their internal native controls remain owned by the game. Blocks expose their
  frame and supported appearance/visibility; ordinary authored elements can be
  composed alongside them or used to replace a screen.
- Real bindings and commands reuse M3's native context/action adapter. The
  minimap image, frame, projection and hit testing share one authored rectangle.
- The Unity bridge stores a persistent visual asset with Undo and reverse export.
  Synchronization previews include hierarchy, order, deletions, component changes,
  bindings and behavior. Pending transactions block further document writes.

## Ownership and reliability

The existing HUD continues to own native content and commands. Authored geometry
owns a registered block's position while active; the old layout does not move it
again before hit testing. Native typography is retained when a block is reparented.
The first full import measures a running match rather than estimating hidden
start-screen widgets. A small width allowance avoids DPI-rounding word breaks.
Resource and idle-worker blocks also retain their native minimum content width
at the current scale. A requested frame can expand to keep its labels readable;
this computed layout is not written back as an authored edit.

Desktop and Unity use the same numeric revision representation. Requests become
visible only after a temporary file is closed and atomically published; approved
requests retry when an earlier queue entry clears. The complete document plus its
future baseline must fit the 16 MiB envelope before Unity is changed. Unknown
native payloads merge as opaque values, retaining unknown arrays without guessing
their structure. Runtime behavior errors can be read back through the snapshot.
