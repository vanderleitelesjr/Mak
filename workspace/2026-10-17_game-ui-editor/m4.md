## Structured context and bounded authority

The assistant understands screen structure, positions, purpose, configuration,
bindings, rules and referenced artwork/effects. Visual-polish assessment is
outside its role. Stable IDs, editable element/rule names, intents and catalog
entries supply semantics without guessing from artwork.

MCP `read_context` provides a compact hierarchy/selection overview. Targeted
`inspect_elements` queries expose authored/effective properties, component
inheritance, parent/children, bindings, effects and computed bounds. Optional
viewport/state/selection/queue scenarios use the same layout and behavior code
as the interactive canvas; simulated state is explicitly distinct from Unity.
Native block interiors remain opaque and game-owned.

`inspect_assets` returns metadata by IDs or pages: original names, relative
paths, hashes, dimensions, crop/stretch borders and usages. It does not read
image bytes. `read_image` requires one manifest image ID, the current visible
revision and a task-specific reason. The owner checks scope, type, hash and
unchanged revision, then returns one image block. Paths, orphan files and fonts
cannot be used to open arbitrary content. The panel's **Open image** uses the
same route. No screenshots or bulk artwork are included automatically.

`read_document` explicitly retrieves the complete saved/draft/base document for
a revisioned proposal. The full portable package remains a manual desktop
export, including original assets and a static SVG reference; the bulk
`export_package` MCP tool is no longer exposed to the model. That reference uses
native placeholders and approximate nine-slice painting, not runtime simulation.

The Codex app-server child has an empty readonly workspace, restricted read
roots and disabled OS commands, image viewer, browser/computer access,
subagents, hooks, plugins, apps and existing MCP connections. Only project
inspection, image-by-ID, project-history reads and proposals are supplied.
Unknown approval requests are refused. The model cannot approve/save its own
proposal, synchronize Unity or execute gameplay actions. The user still reviews
and saves proposals; Unity retains its separate Compare/conflict/Apply boundary.
Global Codex configuration and credentials are not rewritten.

Configured effects describe existing presentation/variable/state/action rules
with event, conditions, targets and parameters. Unsupported shaders, animation
clips/durations and audio playback are identified as unavailable. No new native
capability or document-schema migration is claimed.

## History and persistence

Private `.local/assistant-history.json` version 2 holds local notes, model replies,
model/effort/status, project preferences and the latest request state. It survives
reopening and switching back to a project. Version 1 is migrated only on the first
write, preserving an original-format `.local/assistant-history-v1.json` backup.

All writes use the existing leased project owner and serialized queue. Separate
history revisions reject stale updates; request IDs deduplicate retries.
Partial replies are checkpointed and retained on interruption. Limits remain
2 MiB, 5,000 messages and 64 KiB per message. Capacity is checked before inference;
reaching a limit refuses new writes instead of deleting old messages.

A reconnected native thread receives a bounded recent history excerpt (up to
20 entries/64 KiB), with older project history available through a targeted tool.
Active threads retain their own turns instead of receiving the whole history
again. No other native Codex conversations are imported. Image bytes, account
credentials and private bridge state are excluded from stored chat messages.
History stays outside Git and ordinary project/context/package exports.

Application options live in the application's private user-data directory and
use revision checks plus an OS-backed lease across editor instances. Tests use
isolated state directories, not the user's actual application settings.
