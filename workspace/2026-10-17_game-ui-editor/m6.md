## Owner feedback: first-use authentication, game independence and project folders

Questions and desired product behavior:

- A fresh user needs an understandable agent sign-in flow. The owner asked how
  the tool identifies a user without an already-authenticated local agent.
- The editor must support UI planning/authoring for any game; Global Empires is
  the pilot, not a permanent source of game-specific options for every project.
- Available data, conditions and actions should reflect the linked game's
  actual architecture/functions. The owner is considering generic primitives,
  project adaptation or both; a final integration design is not approved yet.
- Link the UI project to a specific game-project root. Use that link to support
  architecture/catalog discovery and open asset/font import pickers in that
  project's folders.
- Add dark/light appearance modes and additional selectable color schemes in
  the application Options menu.

Verified current implementation: only Codex is connected. Connect finds an
installed Codex CLI and reads its existing ChatGPT session; it does not start
account/login/start or open a login browser. Missing CLI/login causes an error;
API-key fallback is refused. Claude and Antigravity are not current connectors.
Official OpenAI documentation describes managed browser sign-in through the
app-server: start login, open the returned authUrl, await completion. Integrating
that user-facing flow remains proposed work, not a current feature or a fresh
sign-in test. Sources: https://learn.chatgpt.com/docs/auth and
https://learn.chatgpt.com/docs/app-server (read during this turn).

Verified game coupling: behavior.ts imports one global behavior-catalog.json
whose game is Global Empires; typed validation, GE preview data/actions and the
native adapter use that catalog. Generic visual editing and UI state/variable
rules exist, plus semantic intent awaiting a real mapping. Merely selecting a
game folder does not currently discover or integrate its functions.

Recommendation for discussion, not an approved implementation: preserve a
generic authoring/rules core, load a typed data/action catalog per linked game,
and use an engine/game adapter to map those declarations onto real runtime
systems. Source analysis/AI can propose mappings, but symbol names alone do not
prove UI-safe actions, parameter/instance context or functioning runtime bindings.
A game-folder link and an engine integration serve different purposes; importing
assets should continue preserving portable project copies.

Status: recorded feedback and conceptual explanation only. No login, model call,
application change or new connector/catalog implementation was performed.

## What changed

- A current-user Windows x64 installer includes Node, the scoped MCP adapter,
  frontend and third-party notices. English and Portuguese (Brazil) are offered.
- Update/uninstall refuses locked editor or project-host binaries, including
  silent mode (exit 2). The installer never kills the running application.
  Downgrades are refused.
- New default projects live in Documents / Game UI Editor / projects, outside
  installation and disposable application data. Earlier defaults retain their
  existing path. Normal uninstall preserves both locations. Explicitly choosing
  Delete application data can erase a legacy application-data project; copy it
  elsewhere first. The setup guide states this limit.
- Replayable local guidance covers 11 practical topics: projects, hierarchy,
  layout, art/crops/fonts, components, rules/bindings, simulation, saving/recovery,
  Unity review, assistant/MCP and installation. Inspector help opens its relevant
  topic and shows the current selection. Help does not write or call a model.
- The inherited native M1 window title is now Game UI Editor. Runtime preparation
  starts from a clean generated directory and includes frontend license notices
  and version metadata.
- Release staging creates the installer, portable Windows archive, editable
  sources, portable GE pilot and GE-specific Unity source snapshot, with SHA-256
  manifests. Pilot distribution excludes private connections/history/recovery.
